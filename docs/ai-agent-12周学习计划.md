# 从零到 AI Agent 开发 offer：Python 补齐 + 12 周冲刺计划

> 目标：具备「能独立交付一个可用的 AI Agent 产品」的能力，并拿到 Agent / 大模型应用开发岗的面试与 offer。
> 总周期：Python 补齐 7 天（见配套清单 [python-7天补齐清单.md](python-7天补齐清单.md)）+ 12 周主线，约 13 周。
> 每周投入：建议 25~35 小时（全职冲刺可按 1.5 倍压缩到 8 周，在职按 0.6 倍放宽到 16 周）。

---

## 一、开始前：这份计划的前提与三条铁律

### 前提假设
- 你已经能读懂并写出基础代码（任意语言），但 Python 不熟。先用 7 天集中补齐 Python 的语法差异与生态，细节留到项目里边做边补，配套练习见 **python-7天补齐清单.md**。
- 如果完全没写过代码，把 Python 补齐阶段延长到 3~4 周，再从第 1 周开始。
- 你每天能稳定拿出 3~5 小时，且周末至少有一天可以整块投入 6 小时以上。
- 你有可用的模型 API（OpenAI / DeepSeek / 通义千问 / GLM / Kimi 任选；国内网络下优先选 OpenAI 兼容协议的国产模型，接口写法几乎一致，不影响学习效果）。

### 三条铁律（比学什么更重要）
1. **产出驱动，不做教程收藏家**：每学一个概念，当天就要有能跑起来的代码。看视频/读文档的时间不超过 40%，写代码与调试不少于 60%。
2. **手写一遍再上框架**：Agent 的核心循环必须自己用纯 API 写过一次，之后再用 LangGraph / OpenAI Agents SDK 才不至于只会抄配置。
3. **每周一个可演示成果**：能截图、能录屏、能发链接的东西才算做完。求职时别人只看你的仓库和 demo，不看你学了多少小时。

### 立刻要做的环境准备（半天）
- 装 Python 3.11+、VS Code（或 Cursor）、Git、Docker Desktop。
- 建 GitHub 账号，配好 SSH key，学会 `add / commit / push / branch / PR` 五个动作。
- 把 API Key 存进 `.env`，学会用 `.gitignore` 防止密钥泄露（面试会看这个细节）。
- 建一个 `agent-learning` 仓库，每天 push 一次，绿格子本身就是学习证据。

### Python 补齐阶段（第 0 周，7 天）

不要系统学 Python。你的目标是 7 天后能读懂并改写真实 Agent 项目的代码，方法是只补「差异点 + 生态」，其余遇到再学。

| 天 | 主题 | 产出 |
|---|---|---|
| Day 1 | 缩进语法、动态类型、f-string、真值判断 | 写代码不再打大括号 |
| Day 2 | list/dict/tuple/set、切片、推导式、解包 | 能一行推导式替代五行循环 |
| Day 3 | 函数、`*args/**kwargs`、lambda、类型注解 | 能给工具函数写规范的类型注解 |
| Day 4 | 类、`self`、模块导入、Pydantic | 能用 Pydantic 描述工具入参 |
| Day 5 | 文件、JSON、异常、虚拟环境、`.env`、logging | 能建干净环境且密钥不落盘 |
| Day 6 | 生成器、装饰器、async/await、`asyncio.gather` | 看懂流式输出的实现 |
| Day 7 | 串烧实战：命令行 + 真实 API 调用 + 流式 + pytest | 一个能跑、有 README 的小项目 |

**其中三件事必须写熟，后面天天用**：f-string、字典与推导式、类型注解。

**明确跳过**：GUI、爬虫、Django/Flask 全栈、数据分析全家桶、并发底层原理、设计模式。这些对拿 Agent 岗位没有直接帮助。

## 三、逐周详细计划

### 第 0 周（下半段）：认知对齐（与 Python 补齐并行，2~3 天）

**要弄明白的四件事**
- Agent 和普通聊天机器人的区别：Agent 有目标、会自主选择工具、能循环迭代直到完成或放弃。
- Agent 和工作流（Workflow）的区别：工作流是固定步骤，Agent 是模型决定下一步。面试高频题。
- 一个 Agent 的最小组成：模型 + 系统提示词 + 工具 + 循环 + 记忆 + 终止条件。
- 这个岗位实际在做什么：接大模型 API，把公司业务拆成可被模型调用的工具，再解决准确性、成本、延迟、可靠性问题。

**动手**
- 注册一个模型 API，用 20 行代码发一次请求，打印返回内容。
- 把 temperature 分别设为 0 和 1.5，观察同一条 prompt 的输出差异，记录下来。

**检查点**：能用自己的话向外行解释「我和 ChatGPT 的区别是什么」。

---

### 第 1 周：LLM 基础与 API 熟练度

**知识点**
- token、上下文窗口、上下文长度与成本的关系、计费方式。
- system / user / assistant 三种角色的作用，以及为什么 system 提示词影响巨大。
- temperature、top_p、max_tokens 等参数的实际影响。
- 流式输出（streaming）的实现方式。
- 幻觉、知识截止、为什么必须靠检索和工具补足事实。

**动手项目：流式 CLI 聊天机器人**
- 支持多轮对话（自己维护 message 列表）。
- 支持流式打印、支持 `/clear` 清空上下文。
- 支持切换模型、打印本次消耗的 token 数和估算花费。
- 加一个简单的上下文裁剪策略（例如超过 N 轮就丢弃最早的消息）。

**检查点**：能解释「为什么上下文越用越贵」，以及长对话你是怎么做取舍的。

**推荐资料**：所选模型厂商的官方 API 文档（务必以官方文档为准，接口细节更新很快）。

---

### 第 2 周：结构化输出与工具调用

这一周是 Agent 开发的分水岭。工具调用（tool calling / function calling）不熟，后面全部无从谈起。

**知识点**
- JSON 模式与结构化输出的差别，以及怎么用 schema 约束模型输出。
- 工具调用的完整流程：定义 schema → 模型返回工具名和参数 → 你执行 → 把结果回填给模型 → 模型给最终答复。
- 模型返回的 JSON 解析失败怎么办（重试、修复提示、schema 校验）。
- Pydantic 做参数校验的写法。

**动手项目：结构化信息抽取器 + 工具箱**
- 从杂乱文本（简历、发票、新闻）里抽取出固定结构的 JSON。
- 给模型接上至少 3 个真实可用的工具：查天气、算数学、查数据库（SQLite 即可）。
- 有一个工具故意会报错，练习把错误信息回填给模型让它自己纠正。

**检查点**：白板画出一次工具调用的完整回合，说清「谁在什么时候执行了什么」。

---

### 第 3 周：Agent 核心循环（手写，不借助框架）

**知识点**
- ReAct 思路：思考 → 行动 → 观察 → 再思考，直到给出答案。
- 循环的终止条件：拿到最终答案 / 达到最大步数 / 超时或超预算。
- 提示词如何描述可用工具、如何要求模型按固定格式输出。
- 常见失控情形：无限循环、反复调用同一个工具、把工具报错当答案。
- 短期记忆（对话历史）与长期记忆（持久化存储）的区别。

**动手项目：不用任何框架的 ReAct Agent**
- 自己写主循环，自己解析模型输出，自己决定下一步。
- 工具集：网页搜索或本地文件检索、计算器、代码执行（沙箱里跑）。
- 加日志，把每一步的思考、工具调用、观察结果都打印出来——面试时可以拿这个讲全过程。
- 加最大步数限制和成本上限。

**检查点**：如果你只会用框架搭 Agent，说明这周没做完。这一步做完，你会明显比只会拖 `create_react_agent` 的候选人强。

**延伸阅读**：ReAct、Reflexion、Toolformer 这几篇经典论文的摘要，面试聊到「你了解哪些 agent 范式」时用得上。

---

### 第 4 周：框架、记忆与多步骤任务

**知识点**
- 主流框架的定位：LangGraph（状态机 / 图编排，工业界使用广）、OpenAI Agents SDK（轻量、把 agent 当一等公民）、LlamaIndex（偏检索）、CrewAI/AutoGen（多智能体）。
- 何时该用框架、何时不该（框架会掩盖 bug，调试更难，这是很实在的取舍）。
- 记忆方案：会话记忆、摘要记忆、向量记忆、结构化用户画像。
- 人在回路（human-in-the-loop）：关键时刻需要用户确认。
- 重试、降级、超时、幂等这些工程细节在 Agent 里的对应做法。

**动手项目：把第 3 周的 Agent 用 LangGraph 重写一遍**
- 用图的方式表达：模型节点、工具节点、条件边。
- 加上持久化记忆（用 SQLite 或 Postgres 存状态），支持中断后继续。
- 加一个需要用户确认才能执行的危险工具。
- 对比手写版和框架版：代码量、可调试性、可维护性各写三点，这本身就是面试答案。

**检查点**：能说清「LangGraph 的状态是怎么在节点之间传递的」。

---

### 第 5 周：RAG 基础（岗位需求最高的一块）

**知识点**
- 为什么需要 RAG：私有数据、事实准确性、可追溯引用。
- 完整链路：文档加载 → 切分 → 向量化 → 存储 → 检索 → 拼进提示词 → 生成带引用的答案。
- 切分策略（按长度、按语义、按结构）、重叠窗口的作用。
- 向量数据库选型：Chroma / Qdrant / pgvector / Milvus / 云服务，各自适用场景。
- 混合检索：向量检索 + 关键词检索（BM25）互补的原因。
- 重排（rerank）的作用与代价。

**动手项目：文档问答 Agent**
- 把你自己的资料（技术文档、PDF、笔记）灌进去。
- 答案必须带原文引用和出处页码，不能引用就承认「没找到」。
- 支持追问和上下文改写（多轮对话里的指代问题）。

**检查点**：能说清「为什么单纯调大上下文窗口不能取代 RAG」（成本、延迟、召回精度、更新频率）。

---

### 第 6 周：高级检索与检索评测

**知识点**
- 查询改写、多查询检索、HyDE、父子块检索、上下文压缩。
- 元数据过滤、按时间加权、权限过滤（企业场景必备）。
- 检索指标：召回率、精确率、MRR、NDCG 的直观含义。
- 常见答案质量问题：检索不到、检索到了但答错、答对了但引用错。

**动手项目：给上周的 RAG 加评测**
- 手工构造 30~50 条「问题 + 期望答案/期望来源」的测试集。
- 实现自动评测脚本，输出检索命中率和答案正确率。
- 至少做 3 组对比实验（例如：不加 rerank / 加 rerank；固定切分 / 语义切分），把结果做成表格写进 README。

**检查点**：能拿数据说明「你的优化让效果提升了多少」。这是区分「做过 demo」和「做过工程」的关键。

---

### 第 7 周：工程化与可观测性

**知识点**
- FastAPI 写服务端：同步/异步、流式响应（SSE）、请求校验。
- 可观测性：调用链追踪、token 与成本统计、出错率、延迟分位数（P50/P95）。
- 工具：LangSmith、Langfuse、OpenTelemetry 等 trace 方案的用途。
- 缓存（提示词缓存、语义缓存）、限流与重试、并发控制。
- 安全：提示词注入、工具越权、密钥管理、输出内容过滤。

**动手项目：把 Agent 变成真正的服务**
- 用 FastAPI 暴露接口，支持流式返回。
- 接一个最简前端（Streamlit / 纯 HTML 都行），能对话、能看引用、能看耗时。
- 接入 trace 工具，每次调用都能看到完整链路。
- 用 Docker 打包，写清 `docker run` 一条命令就能起。

**检查点**：给出你的服务在 50 次并发请求下的表现与瓶颈分析（哪怕是粗略测试）。

---

### 第 8 周：评测、可靠性与成本

**知识点**
- 评测方法：规则匹配、LLM-as-judge、人工标注的取舍与坑。
- 回归测试：改了提示词或模型后，怎么确保没有变差。
- 成本优化：模型分级路由（简单任务用小模型）、上下文压缩、结果缓存、批量处理。
- 延迟优化：并行工具调用、流式首字延迟、预取。
- 失败模式清单：无限循环、工具误用、幻觉引用、格式崩坏、注入攻击。

**动手项目：给项目加评测与 CI**
- 用 GitHub Actions 跑评测脚本，改提示词后自动出报告。
- 写一份 `FAILURES.md`，记录你遇到的 5 个真实故障、原因和修复方案。

**检查点**：面试官问「怎么保证 Agent 上线不出事」，你能拿出评测集、trace 和失败清单三件套。

### 第 9 周：进阶方向（挑一到两个深入）

**选项 A｜MCP（Model Context Protocol）**
- 理解它的定位：用统一协议把外部数据和工具接到模型上，是当前招聘 JD 里出现频率上升很快的关键词。
- 动手：自己写一个 MCP Server（例如接公司内部文件、数据库或某个 API），发布到 GitHub，写好 README。

**选项 B｜多智能体编排**
- 何时真的需要多个 Agent（角色分工、并行检索、评审-生成分离），何时只是把简单问题搞复杂。
- 动手：做一个「研究员 + 批评者 + 汇总者」的多角色协作流程，并把每步 trace 展示出来。

**选项 C｜语音 / 实时交互**
- 实时语音链路、打断处理、延迟预算。适合做差异化 demo。

**选项 D｜模型微调与蒸馏**
- 了解 SFT、LoRA、偏好优化的大致流程与代价，知道「大多数业务问题不该用微调解决」。会用即可，不必深挖。

**检查点**：至少有一个方向做到「别人可以用」的程度，而不是只跑通 demo。

---

### 第 10 周：作品集定型

你需要三个能撑住整场面试的项目，建议组合：

| 项目 | 展示能力 | 硬性要求 |
|---|---|---|
| 复杂工具型 Agent | 工具设计、循环控制、错误恢复 | 3 个以上真实工具、有失败重试、有 trace 截图 |
| 企业知识库问答 | RAG 全链路、评测意识 | 带引用、有评测集、有 3 组对比实验数据表 |
| MCP Server 或开源小工具 | 工程规范、社区意识 | 有测试、有 CI、有清晰 README、有 issue/PR 记录 |

**每个项目必须包含**
- 一句话说明「解决谁的什么问题」。
- 架构图（一张清晰的图胜过千字说明）。
- 3 分钟以内的演示录屏或在线 demo。
- 关键取舍说明：为什么不选另一个方案，成本与延迟如何。
- 已知缺陷与下一步计划（诚实说明局限性反而加分）。

29. 如何处理模型厂商接口不稳定或限流？

**非技术问题**
- 为什么转行做 Agent 开发？（准备好一段真诚、具体的叙事，不要背模板）
- 你最近读了什么技术资料？学到什么？（保持每周读一篇论文或一篇工程博客的习惯）

**投递策略**

- 渠道：招聘平台关键词搜索 + 公司官网 + 技术社区内推 + GitHub 上主动联系开源项目维护者。
- 投递前用职位描述里的关键词对齐简历（例如 JD 提到 MCP、LangGraph、评测，你的简历就必须出现这些词，且要有对应项目）。
- 每周投递量：15~30 份；同时给 5 家公司写定制化自荐信（说明你能解决它的什么问题，附上相关 demo 链接）。

- 每场面试结束后 1 小时内写复盘：被问倒的问题、答得含糊的地方、对方的业务痛点。

## 五、压缩与放宽版本

- **8 周冲刺（每天 6~8 小时）**：Python 补齐压到 3~4 天（只做 Day 1~5 的精华部分），砍掉第 9 周的进阶方向，把第 2、3 周合并，第 10 周的作品集与第 11 周投递并行。作品集保留「工具型 Agent + RAG 问答」两个精品，胜过三个半成品。
- **16 周稳健版（在职）**：每周只推进半个阶段，把第 5、6 周拆成四周，多留时间在真实业务数据上练习。
- **完全零编程基础**：先用 3~4 周补 Python 与基本 Web 概念，再进入本计划，总周期按 16~20 周预期。

## 六、避坑清单

1. 收藏了 50 个课程，代码写了不到 500 行。→ 每学一个概念必须落到代码。
2. 只会调框架，说不清底层发生了什么。→ 第 3 周的手写循环不许跳过。
3. 项目没有评测数据。→ 没有指标的优化只是感觉，面试官一戳就破。
4. 只做「能跑通」的 demo，没处理失败、成本、并发。→ 工程细节才是招聘方真正要买的。
5. 简历写「熟悉大模型、了解 Agent」却拿不出项目。→ 用项目和数字说话。
6. 追新框架追到晕。→ 核心概念（工具调用、循环、检索、评测）十年内都不会废，框架会换。
7. 只在本地跑，从不部署。→ 至少要有一个可以点开链接体验的 demo。
8. 面试前一周才准备项目讲解。→ 每个项目做完当天就录演示视频。
9. 先花一个月「系统学 Python」再开始做 Agent。→ 语法差异 7 天补完，剩下的在项目里补，效率差三倍。
