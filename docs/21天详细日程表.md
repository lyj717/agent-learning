## 一、每天的时间块模板

以每天约 3~5 小时为参考，**每个 Week 阶段以约 4 个自然日完成为目标**。AI 统筹各 Day 的任务量，把复习、排错、观察和订正都算进阶段预算。每天一个主要新机制；较轻单元可连做，较重单元按整合难度分配时间。每推进 3~4 个新单元，安排半个学习日消化旧问题；每个自然周留半天到一天弹性时间。

**2026-10-19 补充：每次开工先估自然日。** 学员说“开始 DayX”时，AI 先结合当日
内容和实际进度，说明预计需要几个自然日以及主要工作量；超过一天时，说明分天目标和
本次建议先做到哪里。估计须包含复习旧知识、读演示、独立编写与整合、排错、观察和订正。
以学员给出的标准校准：Week 04 前几天那类独立知识点单元约 **1/3～1/2 个自然日**，
**Day 34 按 1 个自然日安排**，整个 Week 约 **4 个自然日**；这是同日学员最新调整，
替代先前 Day 34 1.5～2 天的估计。这是排期基准，不是已测耗时。
轻单元不为凑一天追加任务，重单元不因编号叫 Day 就要求当天完成。

AI 在阶段开工和各 Day 开工时检查剩余任务与预算，主动合并同构练习、复用已学代码、
合理分配前置复习，选修另列；保留核心实现、独立判断和关键失败情境。预计超量时，
先调整重复与非核心范围，再说明剩余工作和新估计；不靠增加学员每日时长来维持排期。

### 新知识与练习日（4 小时示例）

| 时间块 | 时长 | 干什么 |
|---|---|---|
| 块 1｜闭卷回忆 | 20 分钟 | 先说流程或写核心几行，再看旧代码核对 |
| 块 2｜新概念 | 40 分钟 | 读指定文档片段、跑演示，确认本次只新增什么 |
| 块 3｜实现 | 90 分钟 | 自己完成练习并排错 |
| 休息 | 20 分钟 | 可拆到前后时间块之间 |
| 块 4｜变式或排错 | 40 分钟 | 换输入、检查失败路径；较早完成不自动追加新课 |
| 块 5｜观察与反馈 | 30 分钟 | 学员写简短依据，AI 批改；检查、台账与进度维护由 AI 完成 |

### 阶段整合单元（可分多个自然日）

下表是一次投入 3~5 小时的参考；以 Day 34 约一个自然日的量校准，结合本阶段约四天的预算设计整合范围。

| 时间块 | 时长 | 干什么 |
|---|---|---|
| 开始 | 20~30 分钟 | 闭卷画主线，选择本次要接起的部分 |
| 主要时间 | 约 2 小时 | 学员把已练过的部分整合，AI 给接口与验收，减少实现步骤提示 |
| 验证 | 40~60 分钟 | 运行正常与失败情境，换一个问题检查能否独立调整 |
| 收尾 | 20~30 分钟 | 口头讲解、简记限制；AI 更新 README 与交接，休息另留 |

做不完就续到下一次，不把整合、文档、视频、JD 都塞进同一天。正式视频在面试复习时补录；JD 与简历在学习项目结束后统一处理。

### 关键机制的跨天复习

1. 当天：按题干完成，能解释输出；仍不清楚的点如实记录。
2. 完成后 2~3 天：用 10~15 分钟，不看旧答案画流程、写核心逻辑或定位一个已学机制的错误。
3. 阶段末：换问题或数据，只给需求、接口与验收，检验能否独立整合。

AI 在本周 README 的接续点简记复验日期、证据入口和仍需提示之处，不让学员重复填表。一次未通过就针对缺口再练；没有进行的复验不能算通过。正式录视频可以延后，口头复述保留。

**每天开工前 5 分钟的动作**：打开进度文件，写下今天要交付的那「一个东西」。写不出来就先想清楚再动手。

## 二、Python 补齐期：Day 1 ~ Day 7

### Day 1｜语法迁移

| 时间块 | 任务 |
|---|---|
| 热身 | 装好 Python 3.11+、VS Code、Git，建 `agent-learning` 仓库 |
| 学 | 官方 Tutorial 的前几章：缩进、变量、条件、循环、f-string。**只读这几节，不要往下翻** |
| 写 | 完成三个练习：奇偶判断、菲波那契前 20 项、返回最长字符串的函数 |
| 收尾 | 建 `python-notes.md`，写下「和我会的语言的 5 个差异」 |

**验收**：写代码时不再打大括号和分号。
**卡住时**：把报错原文和自己的猜测一起发给 AI，让它指出你猜错在哪。

### Day 2｜容器与推导式

| 时间块 | 任务 |
|---|---|
| 热身 | 重写 Day 1 的三个练习，这次不看笔记 |
| 学 | list / dict / tuple / set、切片、推导式、解包、深浅拷贝 |
| 写 | 三个练习：过滤消息列表、词频统计前 5、拍平嵌套 JSON |
| 收尾 | 把「推导式」和「循环」的写法各写一遍，比较可读性 |

**验收**：能正确处理消息集合，并说明什么时候推导式清楚、什么时候展开循环更好读。
**重点**：`a = b` 不是复制。今天一定要亲手验证一次。

### Day 3｜函数与类型注解

| 时间块 | 任务 |
|---|---|
| 热身 | 用推导式重写昨天的一个练习 |
| 学 | 函数定义、默认参数、`*args/**kwargs`、lambda、类型注解 |
| 写 | 写 `search(query, top_k=5, filters=None)` 并补全类型注解；写排序取前 N 条；故意复现可变默认参数的坑 |
| 收尾 | 在笔记里写下：为什么工具的入参要用类型注解描述 |

**验收**：能解释可变默认参数为什么危险（今天必须亲手踩一次）。

### Day 4｜类、模块与 Pydantic

| 时间块 | 任务 |
|---|---|
| 热身 | 复习类型注解，给昨天的函数补写文档字符串 |
| 学 | 类与 `self`、`__init__`、模块导入、`if __name__ == "__main__"`、Pydantic `BaseModel` |
| 写 | 定义 `Message` 类；用 Pydantic 定义 `ToolCall` 并从 JSON 字符串解析；传非法类型看报错 |
| 收尾 | 把 Pydantic 的校验报错原文记进笔记（后面调试天天遇到） |

**验收**：能独立用 Pydantic 描述一个工具的入参结构。

### Day 5｜文件、异常、环境与包管理

| 时间块 | 任务 |
|---|---|
| 热身 | 默写一个 Pydantic 模型定义 |
| 学 | `with open`、`pathlib`、JSON 读写、`try/except`、虚拟环境、`.env`、`logging` |
| 写 | 读改写一个 JSON 文件；写「读密钥，没有就抛异常」的函数；从零建一个新虚拟环境并装 `httpx`、`pydantic`、`python-dotenv` |
| 收尾 | 确认 `.gitignore` 里已有 `.env`，密钥没有被提交 |

**验收**：能自己从零建干净环境，密钥不进代码、日志和版本库；本地配置按仓库约定管理。
**这个习惯要从今天开始**，面试官会看你有没有把密钥提交上去。

### Day 6｜生成器、装饰器与 async

| 时间块 | 任务 |
|---|---|
| 热身 | 跑一遍昨天的环境，确认依赖还在 |
| 学 | `yield`、装饰器的作用、`async def / await`、`asyncio.gather`、`async for` |
| 写 | 写一个逐字 yield 的生成器；用 `asyncio.gather` 并发请求 3 个网址并对比串行耗时；给一段真实流式示例代码逐行加注释 |
| 收尾 | 用一句话解释「为什么流式输出让用户感觉更快」 |

**验收**：看懂 `async for` 在做什么。这是后面流式对话的基础。
**今天最难**，如果 90 分钟还没通，先抄一个能运行的例子跑通，明天再回来理解。

### Day 7｜串烧实战

| 时间块 | 任务 |
|---|---|
| 块 1 | 规划这个 CLI 小工具的结构，先写 README 的目录 |
| 块 2~3 | 实现：命令行参数 → 读 `.env` 密钥 → 调一次真实模型 API → 流式打印 → 日志记录 |
| 块 4 | 写 1 个 pytest 测试，用 ruff 格式化，push 到 GitHub |
| 块 5 | 口头讲解 3 分钟，指出讲不清的地方；正式视频面试复习时补录 |

**验收**：在干净环境或另一台机器上按 README 复现安装与运行，记录实际环境和结果；不把安装耗时固定为 5 分钟。未做的环境复验继续保留待确认。
**做不完怎么办**：允许延到 Day 8。这个工具质量比进度重要。

## 三、主线第 1 周：Day 8 ~ Day 14（LLM 基础与 API）

本周交付物：**流式 CLI 聊天机器人**（支持多轮、清空、token 与成本统计、错误重试）。

### Day 8｜跑通与参数感知

- 学：官方 Quickstart，弄清 system / user / assistant 三种角色。
- 写：发出最小请求；先核对所用模型与模式是否支持 temperature，再选支持范围内的两个值各跑若干次，固定其他设置。小样本记录现象，不直接推断普遍因果。
- 交付：一份「参数对比记录」，写清 temperature 高低的适用场景。

### Day 9｜token、成本与上下文

- 学：token 是什么、上下文窗口与计费的关系。
- 写：写一个函数估算本次对话的 token 数与花费。
- 交付：成本估算函数；按实际安排，到 Day 10 有 CLI 后再接 `/cost` 命令。

### Day 10｜多轮对话

- 学：message 列表是怎么被维护和发送的。
- 写：实现多轮对话与 `/clear` 清空。
- 交付：能连续追问 5 轮而不串味。

### Day 11｜流式输出

- 学：流式返回的数据结构（结合 Day 6 的 async 知识）。
- 写：实现逐字打印，并处理流中断的情况。
- 交付：打字机效果能稳定跑 10 次不崩。

### Day 12｜上下文管理与容错

- 学：上下文裁剪策略、限流与超时的常见处理方式。
- 写：加「超过 N 轮就丢弃最早消息」的策略和失败重试（指数退避）；简易长期记忆按实际安排移到 Day 13。
- 交付：断网、限流、超长输入三种情况下都不崩溃。

### Day 13｜长期记忆、整合与说明

- 块 1~2：实现简易长期记忆，补齐本阶段欠下的点。
- 块 3：整体打磨，统一日志与错误提示。
- 块 4：写 README（架构说明 + 使用方法 + 已知限制），做口头讲解；视频延后。
- 块 5：push，更新进度文件。

### Day 14｜复盘与面试预热

- 回答并写下：① 为什么上下文越用越贵？② 长对话你怎么取舍？③ 流式输出为什么重要？
- JD 与简历已由学员安排到学习项目结束后，不计入本单元开工或完成门槛。
- 预习下周：搜索并理解「工具调用」和「结构化输出」分别解决什么问题。

## 四、主线第 2 周：Day 15 ~ Day 21（结构化输出与工具调用）

本阶段交付物：**信息抽取与三工具问答双模式项目**（含错误回填与轮数上限），与 Week 02 实际实现一致。

### Day 15｜结构化输出

- 学：JSON 模式与结构化输出的差别，为什么需要 schema 约束。
- 写：从杂乱文本（简历、新闻、发票任选）抽取固定结构的 JSON。
- 交付：跑 10 条文本，分别统计解析成功率与记录级完全匹配率；逐字段统计则另外说明分母。

### Day 16｜Pydantic 与校验

- 学：用 Pydantic 约束模型输出，理解校验失败怎么处理。
- 写：把抽取结果用 Pydantic 模型接收；失败时自动重试一次。
- 交付：故意塞入脏数据，程序不崩且能给出合理结果。

### Day 17｜第一个工具：完整调用流程

- 学：工具调用的完整回合——定义 schema → 模型返回工具名与参数 → 你执行 → 结果回填 → 模型给答复。
- 写：只接一个计算器工具，先跑通最小闭环。
- 交付：画出这次调用的完整流程图（手画也行），标清每一步谁在执行。

**今天的图不要省**，第 11 周面试时你会反复用到它。

### Day 18｜多工具与选择

- 学：工具描述怎么写才让模型选对；工具粒度该粗还是细。
- 写：接上第二个和第三个工具：查天气（模拟）、查 SQLite 数据库（真实）。
- 交付：核对工具选择与参数，记录实际发生的错误或多余调用；没有观察到就如实写，不为凑 3 条制造结论。

### Day 19｜错误处理与自我纠错

- 学：把工具报错当作观察结果回填给模型，让它自己改参数。
- 写：故意让一个工具抛异常，观察模型能否自纠；加最大重试次数防死循环。
- 交付：学员填写练习末尾的观察；AI 根据真实证据维护根 `FAILURES.md`。

### Day 20｜整合

- 块 1~2：补齐欠账。
- 块 3：把抽取器与工具箱整合成一个能用的项目。
- 块 4：写 README、保留真实轨迹与讲解提纲；视频延后。
- 块 5：整理本周的「面试可讲素材」清单。

### Day 21｜复盘与白板演练

- 白板默画出工具调用的完整回合，不看笔记，限时 5 分钟。
- 回答：工具调用陷入死循环怎么排查？工具设计得好和差差在哪？
- JD 统计与简历按学员安排在学习项目结束后统一处理，原交付物中保留待填模板。

## 六、时间不够时的取舍顺序

依次减少：选修与额外框架 → 界面和笔记打磨 → 当天新增内容。保留核心实现、关键失败路径和复验；不足就延长阶段。故障台账与检查由 AI 维护。

只有 25 分钟时，可以用 10 分钟回忆一条数据流、15 分钟验证一个小问题；确实没有时间就休息，不为连续打卡补造产出。视频、JD 和简历沿用已确认的延后安排。
