# 学 Python 和 Agent 该用什么媒介：媒介选择指南

> 结论先说：**媒介要匹配知识类型，不要匹配个人偏好。** 视频、博客、文档、源码没有绝对优劣，只有用错场合。
> 说明：本文提到的资源名以官方渠道为准，我无法联网核实具体链接和课程是否仍在更新，请自己确认一次。

---

## 一、一条规则：先分清你在学哪种知识

| 知识类型 | 例子 | 最佳媒介 | 最差媒介 |
|---|---|---|---|
| **事实性知识**（查得到） | 某个参数叫什么、库怎么装 | 官方文档、速查表 | 视频（信息密度太低） |
| **心智模型**（结构感） | 「Agent 到底是怎么运转的」 | 优质长文、一篇好视频 | 碎片化短视频 |
| **技能**（会做） | 写出工具调用、调通 RAG | 亲手写代码、读源码 | 任何被动观看的媒介 |
| **行业判断**（值不值得学） | 公司到底要什么 | 招聘 JD、工程博客、开源项目 | 培训机构宣传 |

一句话：**查事实用文档，建框架用长文或视频，练技能只能动手，看方向去读 JD。**

---

## 二、五类媒介怎么用

### 1. 官方文档（最高优先级）

**擅长**：准确性、时效性、完整性。永远是对的，永远是新的。
**不擅长**：不给学习路径，新手容易迷路。

**用法**：先读 Official Tutorial / Quickstart，再读 Examples，最后才去翻 API Reference。
**关键认知**：文档是 Agent 开发的主战场，不是补充材料。真实工作里你 60% 的时间在读文档。现在就用起来，等于同时练了工作习惯。

### 2. 视频（建立全局感，不能用来学细节）

**擅长**：快速建立整体印象、看别人怎么排错、学习「思路」而非「语法」。
**不擅长**：容易被「听懂了」的错觉骗到。

**铁律：看视频的时间与写代码的时间比不超过 1:3。**
看完一个视频的当天必须写出对应的代码，否则视为没看。
**优先选**：「从零做一个 X」的项目实战类视频，胜过长篇理论课。看别人卡住、排错、推翻重来的过程，价值高于一切顺利的演示。

### 3. 技术博客（理解取舍与踩坑）

**擅长**：文档不写的东西——为什么选这个方案、踩了什么坑、性能数字是多少。
**不擅长**：质量方差极大，有些是抄的，有些已经过时。

**筛选方法**：看三点。有没有可运行的代码？有没有数据或截图？作者有没有说明局限性？三条都没有就关掉。
**最值钱的类型**：「我们怎样把某个 Agent 做到生产可用」这类工程复盘。

### 4. 源码与开源项目（从会用跨到会改）

**擅长**：真正拉开差距的地方。
**用法**：
1. 先跑起来，再改一行，看行为怎么变。
2. 带着具体问题读，比如「它到底在哪里调用了模型？」不要从头读到尾。
3. 学会看 issue 和 PR，看别人怎么定位 bug——这是最便宜的实战训练。

### 5. 招聘 JD + 社区（校准方向）

**擅长**：告诉你市场现在要什么，避免学一堆用不上的东西。
**用法**：每周读 10 条目标岗位 JD，把反复出现的名词记下来（框架、协议、指标）。出现三次以上的，就是你必须会的东西。
这个习惯的性价比极高：别人的学习大纲可能已经过时，JD 永远是最新的。

## 三、按学习阶段的具体搭配

| 阶段 | 主媒介（70%） | 辅助（20%） | 补充（10%） |
|---|---|---|---|
| Python 补齐（7 天） | 官方 Tutorial + 速查资料 | AI 陪练出题、改代码 | 短视频按需查单个语法点 |
| 第 1~2 周：API 与工具调用 | 官方文档 + 官方示例代码 | 一篇讲清工具调用原理的长文 | 视频看别人的项目结构 |
| 第 3~4 周：Agent 循环与框架 | 官方文档 + 框架官方示例仓库 | 一篇经典工程博客（讲 Agent 与工作流的区别） | 源码挑关键路径读 |
| 第 5~6 周：RAG | 官方文档 + 向量库文档 | 检索相关的经典论文摘要 + 工程博客 | 视频看端到端搭建演示 |
| 第 7~8 周：工程化 | FastAPI / 追踪工具的官方文档 | 别人的开源项目源码 | 社区问答里找同类问题 |
| 第 10~12 周：求职 | 招聘 JD + 投递平台 | 面试经验帖（只参考提问方向） | 技术社区维护人脉 |

## 四、把 AI 当作私教：六个可直接复制的提示词

这是你最快的媒介，但要会问。以下模板按需替换括号内容。

**1. 概念迁移（学语法时最省时间）**
> 我已经会写（你熟悉的语言）代码。请从那个视角解释 Python 的（概念），只讲差异点，各给一个对比例子，最后出 3 道题考我，先不要给答案。

**2. 代码逐行拆解（读源码时用）**
> 逐行解释这段代码在做什么，并单独标出「Python 新手常误解的地方」：（粘贴代码）

**3. 出题陪练（替代刷题网站）**
> 围绕（主题）出 5 道由易到难的练习题，只要题目和验收标准，不要答案。我做完后你再批改。

**4. 代码评审（最被低估的一招）**
> 以资深 Python 工程师的标准 review 我的代码，指出 3 个最值得改的点，说明为什么，并给出修改后的版本：（粘贴代码）

**5. 需求拆解（做项目时防止卡死）**
> 我想做（需求）。请拆成可独立验证的小步骤，每步给出明确的验收标准，并标出哪几步最容易出问题。

**6. 面试模拟（第 11 周开始每天用）**
> 你扮演 Agent 开发岗面试官，就（主题）问我 5 个追问式问题，一次问一个。我回答后，给出评分、我漏掉的关键点，以及下一层追问。

**一条使用原则**：不要让 AI 直接给你完整答案。让它解释、出题、评审、追问——你写代码，它当陪练。直接抄答案会让你在第 11 周的面试里原形毕露。

## 五、资源清单（按类型，按需取用）

### Python
- **Python 官方文档的 Tutorial 与常见问题页**：第一手，最准。
- **Real Python**：英文技术博客，单篇文章质量高，适合按需查。
- **Automate the Boring Stuff with Python**：免费在线书，适合完全没有编程基础的人；你有基础可以只看文件处理、异常、正则几章。
- **中文速查类教程**：适合查语法，不要通读。

### Agent 与 LLM 应用
- **你所用模型厂商的官方文档**：工具调用、结构化输出、流式返回，全部以这里为准。
- **官方示例代码仓库**：抄改官方示例是入门最快的方式。
- **Anthropic 的工程博客（Building effective agents 一类文章）**：讲清 Agent 与工作流的边界，是面试高频话题。
- **Hugging Face 的 Agents 免费课程**：结构完整的入门路径，有练习。
- **DeepLearning.AI 的短期课程系列**：单课 1~2 小时，主题聚焦，适合补单个概念。
- **MCP 官方规范文档**：做第 9 周那个 MCP Server 时的唯一权威来源。
- **经典论文摘要**：ReAct、Reflexion、Toolformer。读摘要和结论即可，面试能聊范式就够了。

### 工程化
- **FastAPI 官方文档**：写作质量很高，本身就是学 Python 工程规范的好材料。
- **Pydantic 官方文档**：结构化输出与参数校验的核心。
- **Docker 官方入门文档**：够用即可。
- **追踪工具（Langfuse / LangSmith 等）官方文档**：接一次就懂。

### 想要底层理解（可选，非必需）
- **3Blue1Brown 的神经网络系列**：建立直觉，不教你写代码。
- **Karpathy 的从零实现系列**：想真正理解 Transformer 再看，属于加分项，不是求职必需项。

## 六、反模式清单（踩了就是在浪费时间）

1. **用视频学语法细节**：信息密度太低，一个 40 分钟视频讲的内容看文档 5 分钟就够。
2. **同时开三个教程**：进度永远停在第三章。选定一个主资源，缺什么补什么。
3. **只收藏不动手**：收藏夹里的资源数量和学习成果零相关。
4. **追最新框架的教程**：框架半年一换，教程永远滞后。只学官方文档。
5. **看「AI 将取代程序员」类内容**：情绪价值高，技能价值零。
6. **等「学完」再开始做项目**：不存在学完的一天，只有交付过的东西。
7. **拿视频里别人的项目当自己的作品**：面试官追问两次就会露馅。可以学思路，必须自己重写。
8. **在中文二手教程里学 API 用法**：永远比官方文档晚半年，而且经常是错的。

---

## 七、一句话总结

**用文档查事实，用一篇好长文或一个项目视频建立框架，用源码和动手练习长本事，用招聘 JD 校准方向，用 AI 当那个随时可问、会出题、会挑你毛病的私教。**
