# 卡住了怎么办：一张排查卡片

贴在旁边，卡住的时候照着走。目标不是「马上就懂」，而是**别在原地空转 20 分钟**。

---

## 第 0 步：先分清你卡在哪一类

不同的卡法，解法完全不同——**认错了类别，再多努力都是白费**。

| 卡法 | 典型感受 | 第一动作 |
|---|---|---|
| **A. 不知道要做什么** | 「这个函数应该怎么实现？」 | 把需求拆成 3~5 个步骤写下来 |
| **B. 不知道某个东西怎么用** | 「`sorted` 的 key 到底要传什么？」 | 查文档 / 写 3 行最小例子试 |
| **C. 报错了但看不懂** | 屏幕上红色的一堆字 | 读报错的**最后一行** |
| **D. 不报错但结果不对** | 「跑是跑了，结果怪怪的」 | 打印中间结果（见下面第 3 招） |

**最容易被误判的是 D。** 没有报错会让人以为「快了」，于是一直盯着代码看——但**看是看不出问题的，必须把中间状态打印出来**。

## 五招（按顺序试）

### 第 1 招：读报错的最后一行

Python 的报错信息是**倒着读**的：最后一行是「什么错」，倒数第二段是「在哪一行」。

```
Traceback (most recent call last):
  File "x.py", line 12, in <module>
    print(fibonacci(3))
  File "x.py", line 8, in fibonacci
    return answers[-1] + answers[-2]
IndexError: list index out of range       ← 先看这一行
```

常见报错的意思：

| 报错 | 大白话 |
|---|---|
| `NameError: name 'x' is not defined` | 这个名字没定义过（拼错了？没赋值？） |
| `TypeError: ... not callable` | 你把它当函数调用了，但它不是函数 |
| `TypeError: unsupported operand type(s)` | 两种类型不能做这个运算（比如字符串加数字） |
| `KeyError` | 字典里没这个键 |
| `IndexError` | 列表下标越界 |
| `AttributeError` | 这个对象没有这个属性/方法（拼错了？类型不对？） |

### 第 2 招：打印中间结果

**把一行拆成三行，每行 print 出来看一眼。**

```python
# 原来是这一行，出问题了
return sorted(counts.items(), key=lambda x: x[1], reverse=True)[:limit]

# 拆开看
pairs = counts.items()
print(f"pairs 是什么：{pairs}")
ranked = sorted(pairs, key=lambda x: x[1], reverse=True)
print(f"排完序：{ranked}")
return ranked[:limit]
```

**看到中间结果的那一瞬间，问题基本就自己跳出来了。**

### 第 3 招：看字符串用 repr

`print(s)` 会「美化」输出，让你看不出问题；`print(repr(s))` 才告诉你里面到底是什么。

```python
s = "a\\nb"  # 以为是换行，其实是反斜杠 + n
print(s)  # a\nb        ← 看不出问题
print(repr(s))  # 'a\\nb'     ← 一眼看出有两个反斜杠
print(s.count("\n"))  # 0           ← 数一下更确定
```

**怀疑字符串有奇怪字符（空格、换行、不可见字符）时，一律用 repr。**

### 第 4 招：写最小复现

把问题从项目里剥出来，在单独一个文件里写 3~5 行。

```python
# 不去改主程序，单独跑这几行
pairs = [("the", 3), ("and", 2)]
print(sorted(pairs, key=lambda x: x[1], reverse=True))
```

好处：没有别的代码干扰，试错成本极低，**几秒钟验证一个猜想**。

### 第 5 招：检查「返回值我接住了吗」

这个坑你已经踩过三次了（`append`、检查项的 `return`、`sorted`）。写完后过一遍：

> 这一行的函数**有返回值**吗？我**接住**了吗？

```python
sorted(x)  # ✗ 算完就扔了
y = sorted(x)  # ✓ 接住了
x.sort()  # ✓ 就地修改，不需要接
```

## 20 分钟规则

**某一个具体问题卡了 20 分钟没有任何进展，就换方法**——不是放弃，是换：

1. 上面五招还没试全 → 试
2. 都试过了 → 去问，但按下面模板问
3. 问完之后 → 把这次的坑写进 `FAILURES.md`

**「没有进展」的定义**：不能说出「我现在怀疑问题在 A，因为 B」。

如果连怀疑的方向都没有，说明你已经不是在思考，是在盯着屏幕——这时候立刻换方法。

## 提问模板

```text
【我想做什么】
top_words 要返回词频最高的前 N 个

【现在的状况】
不报错，但返回的顺序是乱的，而且没有取前 N 个

【我的猜测】
我觉得是 sorted 那行没起作用，但不确定

【已经试过】
print 了 counts，字典本身是对的
把它改成先赋值再 return，还是不对
```

**「我的猜测」这一栏最重要。** 它把「帮我看代码」变成「帮我验证一个假设」，效率差十倍。

## 附：写完代码自查三条

这三条是从「反复犯过的错」里攒出来的。**每次写完一段代码，花 30 秒过一遍。**

### 1. 有返回值的函数，我接住了吗？

```python
sorted(x)  # ✗ 算完就扔
y = sorted(x)  # ✓
x.sort()  # ✓ 就地改，本来就不需要接
```

容易忘的：`sorted`、`sum`、`len`、`.get()`、`.items()`、`str.join()`。
判断方法：**这个函数的返回值有意义吗？** 有，就必须处理它。

### 2. `.get()` 我给了默认值吗？

```python
counts.get(word, 0)  # ✓ 有默认值，语义清楚：没有就当作 0
order.get("items")  # ✗ 没有默认值，等于「不确定这个键在不在」
order["items"]  # ✓ 我认为键一定在，缺了就该当场报错
```

**规则：不打算给默认值，就不要用 `.get()`。**

用 `[]` 报的是 `KeyError: 'items'`，一眼看出是数据缺字段；
用 `.get()` 会得到一个 `None`，然后在别的地方以更难懂的方式炸掉
（比如 `'NoneType' object is not iterable`）。

### 3. 我的循环是在数下标，还是在遍历元素？

```python
for i in range(len(words)):  # ✗ 除非真的需要下标
    print(words[i])

for word in words:  # ✓ 直接拿元素
    print(word)
```

需要序号时用 `enumerate(words)`，不要自己维护计数器。
