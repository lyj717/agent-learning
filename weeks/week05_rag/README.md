### 接口与边界

**Document 转 JSON 答疑（2026-10-24）**：若 A 报
`TypeError: Object of type Document is not JSON serializable`，先运行
[JSON 类型小实验](demos/day40/day40_json_types_demo.py)。它对照直接把 Document
放进字典报错、取出普通字段后转换成功；只用单条的两个字段示意，不提供 A 的批量
五字段实现。`system` 中的文字不会替 Python 生成这些字段，须在调用 `json.dumps`
之前自行整理。学员原实现与题干保留，当前仍在做 A。

- 模型回复是三键 JSON：`status` 为 `answered` 或 `insufficient`，`answer` 是非空
  字符串，`cited_ids` 是原片段 id 列表。能答须有本批引用，资料不足须为空引用。
  这里是本项目约定，JSON 模式不会自动替我们检查业务字段。
- A 收到空证据时返回 `[]`，主程序跳过请求；这是“没有提供候选”的程序结论。
  有候选但缺结束时间时仍请求模型，由它依据资料作出不足回答；不能混为同一种结果。
- B 只检查格式、字段类型、状态与本批编号。已给定的片段来源在旧课核对；回答中的
  每项事实是否被引用支持，今天仍需学员对照原文人工判断，不用分数阈值代替。
- `day40_model_io.py` 是 AI 提供的旧 SDK 运行环境，读取仓库 `.env` 的
  `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`，沿用已配置服务和模型。只发送一次
  JSON 请求，关闭 thinking，`max_tokens=1024`、超时 45 秒、SDK 重试为 0。
  原始响应先打印；结束原因为 `length` 等非 `stop` 时不作为完整答案继续验收。
- 所有内存资料和 B 的错误回答均明确为 AI 手工教具，不计入学员十条自有资料基线。
  今天只填本日记录；自有笔记的选择、约十条问题及期望来源在 Day 41 前分步准备。

## Day 37：切成片段后，怎样仍能找到原文

`langchain-core==1.6.10`，无需安装新的切分包。

今天的产出是能把全文变成一组带原始位置的片段。每段最多几行叫 `chunk_lines`，
相邻段共享几行叫 `overlap_lines`；步长是两者之差。原文行号从 1 开始且包含两端，
Python 切片下标从 0 开始、不包含右端；五行全文在窗口 3、重叠 1 时只有第 1～3、
3～5 行，第一次到文末就停止，不再补一段 5～5 行。

片段仍是 `Document`，返回接口写在练习 A 的题干里：`id` 区分片段，`source` 指向
原文件，`line_start/line_end` 记录原文范围。片段正文按所选原行用换行重新连接，
内部空行和两侧空格保留；原文末尾的换行不额外追加，不承诺字节原样保留。
按行窗口易于核对来源，但不能保证字符或 token 上限，单行过长的边界会在检查入口展示。
