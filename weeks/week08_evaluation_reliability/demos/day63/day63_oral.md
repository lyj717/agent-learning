# Day63 口头解释：三件套 + 发布判断

口述 5～8 分钟，不照读长文；每问先给结论，再给一条证据。
下面只记关键词，AI 会追问。

## 1. 评测集与三层判分

你怎样建评测集？规则、模型裁判、人工各判什么、代价是什么、盲区在哪？

答：从notes/python-notes.md中出题目当作评测集
规则判must_include,must_not_include以及回答的格式,代价最小，都可离线判断，盲区在语义识别
模型裁判判回答是否正确以及引用是否符合回答，代价中等，需要模型调用，盲区是模型可能判断错误以及不遵守裁判规则
人工判规则和模型裁判是否判错，给予最终答案，代价最大，需要人工，盲区是无法将所有回答都人工判断



## 2. trace 与定位失败

一次请求的 trace 至少应包含什么？
拿到一条失败 trace，你按什么顺序定位？

答：至少应该包含一个request的span和一个answer的span
先看有几个request请求，再看每个请求有几个answer，再具体看answer



## 3. 失败清单与 CI

五类失败模式各给一条判据。
哪些能进 push 的 CI，哪些只能手动/人工？

答：
无限循环：steps超过max_steps就失败
工具误用：误用工具必须抛ToolError，成功返回就失败
幻觉引用：cited_ids非空，且每个id都在 evidence_ids 里；否则失败
格式崩坏：解析后键恰好是 status/answer/cited_ids；缺键或非 JSON 抛 FormatError
越权/注入：authorize_tool("delete_file", ...)、("../secret") 必须抛 PermissionError；放行就失败
这五条都能进CI,但具体的语义分析只能手动或人工

## 4. 发布判断

质量、延迟、成本三者冲突时，你怎么决定发不发？
用 Week08 的一个真实数字举例。

答：先看质量再看成本和延迟，质量有问题就绝对不发
Day60 端到端降了 4.5%、费用降了 8.9%，但规则/裁判通过数没降，所以可以采纳；如果质量通过数下降，即使省 8.9% 也不发。


## 追问（口头后作答）

### 追问 1：评测集覆盖

你说从 `notes/python-notes.md` 出题。为什么是这 8 题？
如果笔记里有几十个知识点，你按什么标准选？有没有「资料里没有答案」的题？

答：出题综合考虑，需要包括各种情况：
原计划考虑有答案/无答案两类，实际这 8 题都设计为有答案；无答案题是缺口
易 / 难、单点 / 多点、需引用 / 不需引用；
每题有 must_include、禁词、证据和人工标签等
如果笔记里有几十个知识点，可以出涵盖多个知识点的问题
现有 8 题都是有答案的；没有专门设计「资料里确实没有答案」的题，这是评测集的盲区。以后至少加 1～2 道无答案题，检验模型会不会硬编，或能不能老实说 insufficient



### 追问 2：trace 的字段

一次请求重试两次后成功，`request` 和 `answer` span 各几个？
除了数量，你还要看哪些字段才能判断「时间花在等窗口、上游、还是重试 delay」？

答：request一个 answer三个
看span 名称，status（OK / ERROR），error，start、end、duration， attempt 或重试序号，
request_id / trace_id，每段耗时归属：等窗口、上游、重试 delay。



### 追问 3：质量与强制上线

你说「质量有问题绝对不发」。如果业务强制今天上线，你的做法是什么？
另外 Day60 规则通过是 7/8，不是 8/8，这算不算「质量有问题」？

答：
灰度/开关；
抽样裁判 + 人工复核；
量化回滚条件（answer_ok、引用、P95、费用）；
回滚目标 baseline
不算质量问题，问题本身就在原文中找不到答案，7/8是规则用例与证据不匹配 + 裁判口径问题
