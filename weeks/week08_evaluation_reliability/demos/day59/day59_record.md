## 3. 观察与原因

1. 端到端时间里，检索、首字等待、正文输出各占多少？用 P50 或逐题数字说明，
   哪一段是主要瓶颈？

   答："retrieval_p50": 5.164399975910783  "ttft_p50": 814.0540999593213 "generation_p50": 1210.9623999567702 正文输出 =  1211 −  814 ≈ 397ms
    占比约 0.4% / 67% / 33%，说明首字等待是主要瓶颈

2. P50 和 P95 在这 8 个样本上分别能说明什么、不能说明什么？
   如果要判断线上长尾，还缺什么数据？

   答：能说明这八个样本的中位和最长时间，不能说明样本量大后的数据
   同一题重复后，q07 首字 711～2230ms，说明单次值本身有波动
   还缺大样本量下的p99或者最大值这种数据以及时间窗口、按接口分组等

3. 费用主要来自输入还是输出 token？它和证据长度、回答长度是什么关系？
   用一题的 token 数算一遍。

   答："prompt_tokens": 6970,"completion_tokens": 586
    输出为586 * 8 / 1000000 = 0.004688  输入为 0.017374 − 0.004688 = 0.012686 占比约 27% / 73%
    说明费用主要来自输入，证据长度越长，输入 token 越多，输入费用和首字等待都会受影响

4. 基于这些数据，Day60 应该优化哪一项？写清预期收益、代价与风险，
   以及你会用哪套评测（规则/裁判/人工）验证质量没有变差。

   答：把证据从 3 条缩到 2 条、每块从 8 行缩到 4 行
    预期受益：输入token减少，首字等待和正文输出的时间减少
    代价与风险：可能导致某些证据丢失导致回答错误或者引用不符
    Day57 规则 + Day58 裁判 + 人工抽样，并且前后各跑重复，比中位数而不是单次
