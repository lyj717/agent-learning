## 3. 观察与原因

1. 基线自检的 regressed、fixed、still_failing 各是什么？为什么自检不是「四类全空」，
   怎样用这三类判断判分器与基线是不是同一口径？
   - regressed：无
   - fixed：无
   - still_failing：q02、q08
   baseline 里本来就有 q02、q08 两个已知失败，重放时它们仍失败，所以 still_failing 不是空,「四类全空」只有在 baseline 全部通过时才可能出现。
   regressed 和 fixed 都为空并且still_failing / unchanged_pass 的题号与 baseline 的失败/通过划分完全一致才是同一口径
2. v1 和 v2 的通过数相同。只报「通过 6/8」会漏掉哪两题、各是什么方向的变化？
   为什么这种情况必须按题号对比，而不能只看总数？
   会漏掉q02和q03，第2题v1失败v2通过，第3题v1通过v2失败，如果只看总数不能发现题目的对错变化，不知道具体情况
3. 规则判通过不等于语义正确。在 v2 的通过项里找一题，对照
   `notes/python-notes.md` 的原文，判断回答是否真的正确；若发现不一致，写出题号、
   错在哪，以及规则为什么没拦住它。
   q04回答错误，原文先 append 攒进列表，最后用 "\n".join(列表)；不要边循环边 +=，回答为不要用 "\n".join(列表)，直接在循环里把每行 += 到字符串上更省事
   因为q04的"must_include": ["join"]，只要回答中有join并且符合其他规则就判断正确，肯定句和否定句都包含 join，所以都通过
4. 如果要让这套检查每次提交都自动跑，哪一部分可以直接进 CI，哪一部分必须留给
   模型裁判或人工？结合本日实际输出说明理由。
   规则层如judge_answer + compare_baseline + 冻结基线可以直接进入CI
   语义正确性、引用是否真的支持结论、模型裁判的一致性必须留给人工
   规则层能够离线重复所以可以直接进入CI，语义正确性、引用是否真的支持结论都需要人工真实审查，规则是做不到的
   （以下是 AI 从今日运行日志补的证据，判断句仍用你自己的写法，可自行改写合并）
   - 规则层能离线重复：A 14/14、B 9/9；regression 的配置 `model_calls=0`，不读密钥。
   - 它抓到了真实变化：q03 在 v1 通过、v2 失败，被 `regressed` 抓住；q02 修好记为 `fixed`。
   - 它看不见语义：q04 规则判通过，但对照 `notes/python-notes.md` 第 24 行，回答把
     `join` 和 `+=` 说反了。
   - 已知失败不拦流水线：q08 两版都失败，留在 `still_failing`，应进报告而不是让 CI 失败。
   - 语义层要额外代价：模型裁判需要真实调用（Day58 计划 8～12 次），有费用和波动；
     引用是否支持结论要人读原文，当前规则只查编号在不在 `retrieved_ids` 里。
