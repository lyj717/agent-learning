# Week 08｜评测、可靠性与成本

**交付物**：自动评测集 + GitHub Actions CI 回归报告。

## 必做顺序

- [ ] 复用前面已有案例，把确定性检查接入 CI；真实模型评测使用明确的手动入口或受控预算
- [ ] 在已有人工判分基础上试模型裁判，抽样比较分歧，说明规则、模型与人工各自能判断什么
- [ ] 根据瓶颈选择一个成本或延迟优化，比较效果是否退化
- [ ] 报告任务成功率、引用质量、用量与延迟，明确样本来源与判分口径
- [ ] AI 继续维护根 `FAILURES.md`；学员选真实案例练习讲解，不为数量制造故障

## 选修

分级路由、上下文压缩、缓存、并行工具与预取按证据选用，不要求全接。若已有优化已解决主要瓶颈，优先保留稳定版本与回归证据。

## 验收标准

- [ ] 被问「怎么保证上线不出事」，能拿出评测集 + trace + 失败清单
- [ ] 能说明这些检查能发现什么、仍有哪些覆盖不到的风险，不承诺测试通过就绝不出错
