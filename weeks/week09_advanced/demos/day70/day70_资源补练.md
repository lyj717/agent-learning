# Day70 资源补练（闭卷，10～15 分钟）

先跑一遍 [day70_resource_refresh.py](day70_resource_refresh.py)，再闭卷答。
每题 1～3 句；答完告诉 AI，答案留在这份文件里。

## 1. 两个错误码

`note://missing.md` 返回 `-32603`，`other://x` 返回 `-32602`。分别是什么原因？客户端能从这个 code 知道真实原因吗？

答：`note://missing.md` 返回 `-32603`是因为内部处理失败，`other://x` 返回 `-32602`是因为没有找到这个资源
客户端不能知道真实原因，只知道-32602是找不到路由，-32603是找到路由但处理失败

## 2. index 是什么

`note://index` 返回的内容是什么类型、几行？谁负责读它？模型会自己来读吗？

答：返回的是str类型，行数=笔记篇数。由宿主自己读，宿主读完可以把内容塞进消息，模型不会自己读

## 3. 模板展开

`{path}` 与 `{+path}` 对 `notes/python-notes.md` 的匹配结果有什么不同？如果把 `note://` 的模板从 `{+path}` 改成 `{path}`，哪类路径会读不到？

答：{path}读不到，{+path}能读到；从 `{+path}` 改成 `{path}`，带/的路径会读不到

## 4. 模型怎么知道有哪些笔记

宿主想让模型「知道有哪些笔记」，该由谁、在哪一步做？为什么不能指望 `resources/list` 自动做到？

答：由宿主在启动服务后，第一次模型请求前就把内容拼进系统提示或首条用户消息。因为resources/list 是给宿主看的，模型不会主动去读list清单，只能由宿主交给模型
