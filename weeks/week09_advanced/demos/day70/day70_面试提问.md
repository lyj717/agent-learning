# Day70 模拟面试（文件作答）

规则：每题先用 60～90 秒口述一遍（或默讲一遍），再把要点写进「答：」下面。
每题后面的「追问」要接着答，一共 3 个主问题 + 6 个追问；写关键词即可，不用成文。

## 第 1 问：给谁用

这套 server 给谁用？不装它的时候对方现在怎么做？为什么值得做？

答（第 1 问已在聊天里答过，这里补录原话）：
给个人使用，不装它的时候，这个人要打开 notes/ 文件夹，Ctrl+F 搜「流式」，把命中的几段复制到对话框里，再让模型总结。装了以后模型自己调 search_notes，拿到「文件 + 行号」，直接回答。节省了很多时间

### 追问 1.1

「节省时间」具体省在哪一步？能说个量级吗？

答：不用自己去文件里找关键词，只需要把关键词交给模型，模型会自动输出文件行号

### 追问 1.2

notes/ 只有 4 篇、约 50KB，直接把整个目录贴给模型也能答，为什么还要做检索工具？

答：文件一旦多起来，模型要处理的上下文就多很多，不仅大幅提高成本，还会干扰ai判断

## 第 2 问：怎么用

别人拿到仓库，怎么装、怎么配进宿主、怎么让它指向自己的笔记目录？

答：按项目readme来装：pip install -e，配进宿主要看宿主是什么应用程序，如Claude Desktop的配置如下
{
  "mcpServers": {
    "notes": {
      "command": "C:\\path\\to\\python.exe",
      "args": ["-m", "projects.mcp_server.server"],
      "env": {"NOTES_ROOT": "C:\\path\\to\\notes"}
    }
  }
}
读环境变量 NOTES_ROOT，不设默认值时用仓库里的 notes/ 目录
### 追问 2.1

Claude Desktop、Cursor、VS Code 的配置文件分别在哪个位置、外层键各是什么？哪个还要 `type`？

答：Claude Desktop在claude_desktop_config.json，外层键是mcpServers
Cursor在.cursor/mcp.json，外层键也是mcpServers
VS Code在.vscode/mcp.json，外层键是servers，需要type

### 追问 2.2

`NOTES_ROOT` 由谁设置、谁读取？不设时用什么？为什么不在代码里写死？

答：由宿主设置，notes_root读取，不设时用仓库里的 notes/ 目录
不在代码里写死是方便换一套笔记不用改代码、不同人配不同目录

### 追问 2.3

宿主配置里的 `command` 为什么必须写绝对路径？写相对路径会发生什么？

答：宿主从自己的目录启动，相对路径相对的是宿主，不是仓库，所以会找不到

## 第 3 问：出问题怎么办

线上有人反馈「模型答得不对/工具没反应」，你按什么顺序排查？

答： 先看宿主轨迹（调没调、调了什么、返回什么）→ 再核对引用与原文 → 再复现（NOTES_ROOT/路径）→ 最后才怀疑模型
### 追问 3.1

工具失败和资源失败在客户端分别长什么样？模型能看到哪一个的原因？

答：工具失败是result的is_error为true，资源失败是mcperror
模型能看到工具失败的原因

### 追问 3.2

资源读不到时，真实原因在哪里？客户端只看到什么？你怎么定位到具体原因？

答：真实原因在server端handler抛的异常，客户端只看到-32603
定位靠 server 日志/自己复现

### 追问 3.3

模型不调工具、或者调错工具，你先看哪几样东西？举一个你实际遇到过的例子。

答：先看模型返回的json，看有没有tool_calls字段，如果没有说明模型没有调工具
如果有再看name，看是否工具调错
