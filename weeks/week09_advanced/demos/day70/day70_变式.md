# Day70 阶段变式（闭卷，约 40～50 分钟）

闭卷：不翻演示、不翻代码、不翻记录。写完直接告诉 AI，答案留在这份文件里。
每题 2～5 句；能用文件路径/函数名举例就举例。

## 1. 一次「模型决定调用工具」的完整路径

从模型输出到工具执行、再回到模型，经过哪些角色？哪一步发的是 JSON-RPC？宿主和 client 分别做了什么？

答：宿主启动服务准备将问题，可能需要的资源，提示词等，client发送请求给server，模型读过问题向宿主请求工具调用并规定工具名和参数
client收到请求，将工具请求交给server，由server执行，得到工具答案后client将答案交给宿主，宿主交给模型
client将工具请求交给server以及server将答案交给client时发的是JSON-RPC
宿主负责启动服务，并发布命令
client负责发请求/收响应

## 2. `inputSchema` 从哪来

`tools/list` 里的参数表是谁生成的、读的是函数里的什么？如果工具描述写得很含糊，会在哪一步出问题？

答：是mcp生成的，读的是类型注解和默认值，描述来自docstring
如果工具描述写得很含糊，模型在调用时可能会出现选错工具，写错参数格式等问题

## 3. 两种失败形态

工具失败、资源失败在客户端分别长什么样？`-32602` 和 `-32603` 各代表什么？模型分别能不能看到原因？

答：工具失败是result，is_error为true，资源失败是mcperror
-32602是未知资源URI，-32603是处理器异常
模型能看到工具失败的原因，看不到资源失败的原因

## 4. 资源：index 与模板

`note://index` 和 `note://{+path}` 各解决什么问题？为什么 `index` 不能代替读正文？`{+path}` 里的 `+` 去掉会怎样？

答：note://index负责固定路径下列出笔记的相对路径清单，note://{+path}负责提供模板，读指定path下的正文
index列出所有的相对路径，全部读既浪费token还可能给模型提供用不上的信息
`{+path}` 里的 `+` 去掉会导致一些路径无法读取

## 5. 传输与日志

stdio 和 Streamable HTTP 各适合什么场景？stdio 下为什么 stdout 不能当日志？我们的宿主为什么必须用 `StdioServerParameters` 启动 server？

答：stdio适合本地单机场景，Streamable HTTP适合异地多机场景
服务开始前的 print 会写进协议通道、客户端第一行就不是 JSON；服务期间 SDK 接管 stdout，print 输出会丢，不能当日志
用 `StdioServerParameters` 启动 server是因为在宿主是另一个应用/进程，靠import来启动server行不通


## 6. 打包

`[project.scripts]` 右边写什么？装好后命令怎么找到 `main`？版本号在哪两处、怎么保证不漂？`LICENSE` 放哪、为什么？

答：右边写模块:函数，装好后会自动导入包，由import可以找到main；版本号分别在`pyproject.toml`和`projects/mcp_server/__init__.py`，为了保证不漂版本号以pyproject.toml为准，projects/mcp_server/__init__.py里的版本号必须严格与pyproject.toml保持一致
`LICENSE`放在和pyproject.toml同级的文件夹下，因为分发的根在仓库根，GitHub 也只认根目录的 LICENSE

## 7. 测试分工

进程内 `Client(mcp)` 和 stdio 冒烟各测什么？stdio 冒烟为什么必须 `timeout`？如果只用进程内测试，会漏掉哪类问题？

答：进程内 `Client(mcp)`测契约（工具在不在、参数校验、返回结构、is_error），stdio测能不能启动、空 stdin 能不能退出、环境变量有没有传进去、协议通道通不通；
冒烟如果没有timeout限制可能会导致无限挂起，如果只用进程内测试，会漏掉启动失败、协议帧错、环境变量没继承、挂死这类等问题
